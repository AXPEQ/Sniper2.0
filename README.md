# Sniper 2.0: снайпер мем-коинов pump.fun (Solana)

Бот ловит новые токены на pump.fun в момент создания, прогоняет их через фильтры безопасности,
покупает на заданную сумму и сам продаёт по тейк-профиту, стоп-лоссу, трейлинг-стопу или таймауту.
По умолчанию работает **в режиме симуляции**: всё считается на реальных данных mainnet, но сделки не отправляются.

```
 WebSocket logsSubscribe ─► CreateEvent ─► быстрые фильтры ─► глубокие фильтры ─► покупка ─► позиция
   (программа pump.fun)      (парсинг)     (имя, дубли,        (метаданные, mint,    (PumpPortal,   (обновления кривой
                                            mayhem, blacklist)  кривая, dev %)        или симуляция)  по WebSocket → TP/SL)
```

## ⚠️ Прочитайте до запуска

- **Большинство мем-коинов падают до нуля.** Фильтры отсекают очевидный скам, но не гарантируют прибыль.
  Настройки по умолчанию — отправная точка, а не прибыльная стратегия.
- **Симуляция оптимистична.** Она считает вход по цене на момент проверки. В реальности вашу транзакцию
  опередят другие снайперы, а цена входа будет хуже. Сначала погоняйте бота в симуляции, потом проверьте
  live на минимальной сумме.
- **Стоп-лосс может проскальзывать.** Если разработчик сливает всё одной продажей, цена падает на 40–90%
  за один блок, и продажа пройдёт уже ниже порога.
- **Используйте отдельный кошелёк** с небольшой суммой. Не храните на нём ничего ценного. Файл `.env`
  с ключом не попадает в git (он в `.gitignore`), никому его не отправляйте.

## Быстрый старт

Нужен Node.js 20+.

```bash
npm install
cp .env.example .env      # при желании отредактируйте настройки
npm start                 # запуск (по умолчанию DRY_RUN=true)
```

Остановка: `Ctrl+C`. Итог по PnL выводится в консоль, все сделки пишутся в `data/trades.jsonl`.

Для реальной работы нужен **приватный RPC**: публичный `api.mainnet-beta.solana.com` режет запросы (HTTP 429)
и даёт задержку. Подойдут Helius, QuickNode, Triton, Shyft и т.п. Укажите `RPC_URL` (и `WS_URL`, если нужно).

## Переход на реальную торговлю

1. Создайте новый кошелёк и пополните его небольшой суммой SOL.
2. В `.env` укажите `PRIVATE_KEY=<base58>` (такой формат экспортирует Phantom/Solflare) и `DRY_RUN=false`.
3. Поставьте маленькие `BUY_AMOUNT_SOL` и `MAX_TOTAL_SPENT_SOL`.
4. Запустите `npm start`. В логе появится `БОЕВОЙ РЕЖИМ` с адресом и балансом кошелька.

Сделки идут через [PumpPortal Local Transaction API](https://pumpportal.fun/local-trading-api/trading-api):
сервис собирает транзакцию (bonding curve pump.fun или PumpSwap после миграции), а бот **подписывает её
локально**, так что приватный ключ никуда не уходит. PumpPortal берёт 0.5% с каждой сделки.

Транзакция собрана третьей стороной, поэтому перед подписью бот её проверяет:
- fee payer должен быть вашим кошельком, а все программы — из белого списка
  (System, ComputeBudget, Token, Token-2022, ATA, pump.fun, PumpSwap, роутер PumpPortal);
- транзакция симулируется: она не должна падать, а кошелёк не должен терять больше суммы сделки,
  комиссий и запаса на ренту (`SIMULATE_BEFORE_SEND=true`, добавляет ~100–300 мс).

## Фильтры

| Фильтр | Настройка | Что проверяет |
|---|---|---|
| Mayhem mode | `SKIP_MAYHEM` | Токены, которыми торгует AI-агент pump.fun: у них нестандартная кривая |
| Стоп-слова / ключевые слова | `NAME_BLACKLIST`, `NAME_WHITELIST` | Имя и тикер |
| Копикэты | `SKIP_DUPLICATE_NAMES`, `DUPLICATE_WINDOW_MINUTES` | Повтор имени или тикера за последние N минут |
| Чёрный список создателей | `CREATOR_BLACKLIST` | Адрес подписанта или creator |
| Соцсети | `REQUIRE_SOCIALS` | Twitter/Telegram/сайт в метаданных (IPFS с фолбэком по шлюзам) |
| Mint | всегда | Mint и freeze authority отозваны; нет опасных расширений Token-2022 (permanent delegate, transfer hook, transfer fee, non-transferable, pausable, заморозка по умолчанию) |
| Капитализация | `MIN_MARKET_CAP_SOL`, `MAX_MARKET_CAP_SOL` | mcap на момент проверки; отсекает нестандартные кривые и токены, которые уже улетели |
| Доля разработчика | `MAX_DEV_HOLDING_PCT` | Сколько supply у подписанта и creator |
| Топ-10 холдеров | `MAX_TOP10_HOLDING_PCT` | Концентрация без учёта bonding curve (тяжёлый запрос, имеет смысл с `BUY_DELAY_MS`) |

Любая ошибка при проверке (RPC недоступен, таймаут метаданных) считается отказом: бот не покупает то,
что не смог проверить.

## Выход из позиции

Обновления bonding curve приходят по WebSocket (`accountSubscribe`), плюс резервный опрос раз в `PRICE_POLL_MS`.
Стоимость позиции считается по формуле кривой с учётом комиссии. Бот продаёт, когда срабатывает первое из условий:

- **тейк-профит**: PnL ≥ `TAKE_PROFIT_PCT`;
- **стоп-лосс**: PnL ≤ −`STOP_LOSS_PCT`;
- **трейлинг-стоп**: после роста на `TRAILING_ACTIVATION_PCT` цена откатилась на `TRAILING_STOP_PCT` от пика;
- **таймаут**: позиция открыта дольше `MAX_HOLD_SECONDS`;
- **миграция**: кривая заполнена и токен ушёл в PumpSwap. Цена на кривой больше не обновляется,
  поэтому бот продаёт через PumpSwap.

Если продажа не прошла, бот повторяет попытку с нарастающей паузой (до 30 с).

Все настройки с пояснениями лежат в [`.env.example`](.env.example).

## Анализ результатов

Каждая покупка и продажа записывается строкой JSON в `data/trades.jsonl`:

```bash
# итоговый PnL и число сделок
jq -s '[.[] | select(.type=="sell")] | {trades: length, pnl: (map(.pnlSol) | add)}' data/trades.jsonl
# разбивка по причинам выхода
jq -s '[.[] | select(.type=="sell")] | group_by(.reason) | map({reason: .[0].reason, n: length, pnl: (map(.pnlSol) | add)})' data/trades.jsonl
```

## Структура проекта

```
src/
  index.ts              точка входа, сборка компонентов, корректная остановка
  config.ts             загрузка и валидация настроек из .env
  listener.ts           подписка на логи pump.fun, вотчдог переподключения
  sniper.ts             оркестратор: фильтры → покупка → позиция, лимиты и бюджет
  positions.ts          позиции, TP/SL/трейлинг/таймаут, продажа с повторами
  journal.ts            журнал сделок (JSONL)
  pump/events.ts        парсер CreateEvent (Anchor event из логов)
  pump/bondingCurve.ts  PDA, раскладка аккаунта кривой, формулы покупки/продажи, mcap
  filters/              фильтры безопасности и загрузка метаданных
  trader/
    dryRun.ts           симуляция сделок
    pumpPortal.ts       реальные сделки через PumpPortal
    guard.ts            проверка и симуляция транзакции перед подписью
    txSender.ts         отправка с переотправкой и ожиданием подтверждения
test/                   юнит-тесты (в т.ч. на реальных событиях из mainnet)
```

## Идеи для следующих версий

- Отправка через Jito bundles или сервисы быстрой доставки (Nozomi, bloXroute) для приоритета в блоке.
- Частичный тейк-профит (например, продать 50% на x2, остальное держать с трейлингом).
- Отслеживание цены в PumpSwap после миграции вместо немедленной продажи.
- Telegram-бот: уведомления о сделках и управление командами.
- Проверка истории создателя (сколько токенов он запускал и как они закончились).
