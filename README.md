# Sniper 2.0: снайпер мем-коинов pump.fun (Solana)

Бот ловит новые токены на pump.fun в момент создания, наблюдает за первыми сделками, прогоняет токены
через строгие фильтры, покупает на заданную сумму и сам продаёт по тейк-профиту, стоп-лоссу,
трейлинг-стопу или таймауту.

По умолчанию работает в режиме **бумажной торговли**: виртуальный кошелёк, но реальные цены mainnet
и реалистичное исполнение.

```
 WebSocket logsSubscribe ─► новый токен ─► быстрые фильтры ─► окно наблюдения ─► глубокие фильтры ─► покупка ─► позиция
   (программа pump.fun)      CreateEvent    имя, копии,        6с: сделки         метаданные, mint,   PumpPortal  обновления кривой
                             + TradeEvent   mayhem             (TradeEvent)       кривая, холдеры,    или paper   по WebSocket → TP/SL
                                                                                  активность торгов
```

## ⚠️ Прочитайте до запуска

- **Большинство мем-коинов падают до нуля.** Фильтры отсекают очевидный скам, но не гарантируют прибыль.
  Пороги по умолчанию — отправная точка, их нужно подбирать по результатам бумажной торговли.
- **Бумажная торговля ближе к реальности, но не равна ей.** В реальности на вход влияют конкуренты,
  загрузка сети и качество доставки транзакций.
- **Стоп-лосс может проскальзывать.** Если разработчик сливает всё одной продажей, цена падает на 40–90%
  за один блок, и продажа пройдёт уже ниже порога.
- **Используйте отдельный кошелёк** с небольшой суммой. Файл `.env` с ключами не попадает в git
  (он в `.gitignore`), никому его не отправляйте.

## Быстрый старт

Нужен Node.js 20+ и ключ RPC (например, бесплатный ключ [Helius](https://helius.dev)).

```bash
npm install
cp .env.example .env      # впишите HELIUS_API_KEY=ваш-ключ
npm start                 # бумажная торговля со строгими фильтрами
npm run report            # отчёт по сделкам
```

Остановка: `Ctrl+C`. Каждую минуту бот печатает статус, частые причины отказа и виртуальный баланс.

## Бумажная торговля (не настоящими деньгами)

Включена по умолчанию (`DRY_RUN=true`). Приватный ключ не нужен.

- **Виртуальный кошелёк** со стартовым балансом `PAPER_BALANCE_SOL` (по умолчанию 5 SOL). Баланс и
  статистика сохраняются в `data/paper-wallet.json` и переживают перезапуски. Сброс: `PAPER_RESET=true`.
- **Реалистичное исполнение.** Бот ждёт `SIM_LATENCY_MS` (как будто транзакция летит в сеть), заново
  читает кривую и исполняет сделку по новой цене. Если цена ушла дальше `BUY_SLIPPAGE_PCT`/`SELL_SLIPPAGE_PCT`,
  «транзакция падает» и списывается только комиссия, как в реальности.
- **Все издержки учтены:** комиссии pump.fun (1.25%) и PumpPortal (0.5%), priority fee и рента
  токен-аккаунта (~0.002 SOL).
- Все сделки пишутся в `data/trades.jsonl`, вместе со статистикой торгов на момент входа.
  `npm run report` покажет PnL, процент сделок в плюс, разбивку по причинам выхода, лучшие и худшие сделки.

## Строгие фильтры

`FILTER_PRESET=strict` (по умолчанию) или `normal`. Пресет задаёт пороги, любой можно переопределить в `.env`.

**Строгий режим не покупает сразу.** Сначала бот 6 секунд наблюдает за сделками нового токена
(они приходят в той же WebSocket-подписке, без лишних запросов) и только потом решает.

| Проверка | strict | normal | Настройка |
|---|---|---|---|
| Окно наблюдения | 6 с | нет | `BUY_DELAY_MS` |
| Уникальных покупателей (без разработчика) | ≥ 8 | — | `MIN_UNIQUE_BUYERS` |
| Объём покупок за окно | ≥ 2 SOL | — | `MIN_BUY_VOLUME_SOL` |
| Продажи относительно покупок | ≤ 50% | — | `MAX_SELL_RATIO` |
| Разработчик продаёт | отказ | — | `REJECT_DEV_SELL` |
| Доля одного кошелька в покупках | ≤ 35% | — | `MAX_SINGLE_BUYER_PCT` |
| Покупателей в блоке создания (бандл/инсайдеры) | ≤ 3 | — | `MAX_BUNDLED_BUYERS` |
| Цена относительно старта | от 0% до +150% | — | `MIN_PRICE_CHANGE_PCT`, `MAX_PRICE_CHANGE_PCT` |
| Капитализация | 25–70 SOL | 20–60 SOL | `MIN_MARKET_CAP_SOL`, `MAX_MARKET_CAP_SOL` |
| Доля разработчика | ≤ 5% | ≤ 10% | `MAX_DEV_HOLDING_PCT` |
| Топ-10 холдеров (без bonding curve) | ≤ 30% | — | `MAX_TOP10_HOLDING_PCT` |
| Баланс разработчика | ≥ 0.1 SOL | — | `MIN_DEV_SOL_BALANCE` |
| Ссылка на X/Twitter и картинка | обязательны | — | `REQUIRE_TWITTER`, `REQUIRE_IMAGE` |

Проверки в обоих режимах:
- хотя бы одна соцсеть в метаданных (`REQUIRE_SOCIALS`);
- mint и freeze authority отозваны, нет опасных расширений Token-2022 (permanent delegate, transfer hook,
  transfer fee, non-transferable, pausable, заморозка по умолчанию);
- пропуск mayhem-токенов (`SKIP_MAYHEM`): с ними торгует AI-агент pump.fun, кривая нестандартная;
- пропуск копий имён и тикеров (`SKIP_DUPLICATE_NAMES`);
- стоп-слова, ключевые слова, чёрный список создателей (`NAME_BLACKLIST`, `NAME_WHITELIST`, `CREATOR_BLACKLIST`).

Любая ошибка при проверке (RPC недоступен, таймаут метаданных) считается отказом: бот не покупает то,
что не смог проверить.

**Как подбирать пороги.** На живом прогоне строгий режим пропускал примерно 1 токен из 100–150.
Если покупок слишком мало, смотрите строку «Частые причины отказа» в логе и ослабляйте самый частый фильтр.
Если сделки в основном убыточные, ужесточайте фильтры и сравнивайте результаты через `npm run report`.

## Выход из позиции

Обновления bonding curve приходят по WebSocket (`accountSubscribe`), плюс резервный опрос раз в `PRICE_POLL_MS`.
Бот продаёт, когда срабатывает первое из условий:

- **тейк-профит**: PnL ≥ `TAKE_PROFIT_PCT`;
- **стоп-лосс**: PnL ≤ −`STOP_LOSS_PCT`;
- **трейлинг-стоп**: после роста на `TRAILING_ACTIVATION_PCT` цена откатилась на `TRAILING_STOP_PCT` от пика;
- **таймаут**: позиция открыта дольше `MAX_HOLD_SECONDS`;
- **миграция**: кривая заполнена и токен ушёл в PumpSwap. Цена на кривой больше не обновляется,
  поэтому бот продаёт через PumpSwap.

Если продажа не прошла, бот повторяет попытку с нарастающей паузой (до 30 с).

## Переход на реальную торговлю

1. Погоняйте бота в бумажном режиме и убедитесь по `npm run report`, что результаты вас устраивают.
2. Создайте новый кошелёк и пополните его небольшой суммой SOL.
3. В `.env` укажите `PRIVATE_KEY=<base58>` (такой формат экспортирует Phantom/Solflare) и `DRY_RUN=false`.
4. Поставьте маленькие `BUY_AMOUNT_SOL` и `MAX_TOTAL_SPENT_SOL`.

Сделки идут через [PumpPortal Local Transaction API](https://pumpportal.fun/local-trading-api/trading-api):
сервис собирает транзакцию, а бот **подписывает её локально**, так что приватный ключ никуда не уходит.
PumpPortal берёт 0.5% с каждой сделки. Перед подписью бот проверяет транзакцию:
- fee payer должен быть вашим кошельком, а все программы — из белого списка
  (System, ComputeBudget, Token, Token-2022, ATA, pump.fun, PumpSwap, роутер PumpPortal);
- транзакция симулируется: она не должна падать, а кошелёк не должен терять больше суммы сделки,
  комиссий и запаса на ренту (`SIMULATE_BEFORE_SEND=true`).

## Подключение

- `HELIUS_API_KEY=ключ` — RPC и WebSocket Helius соберутся автоматически.
- Или `RPC_URL` (и при необходимости `WS_URL`) любого другого провайдера: QuickNode, Triton, Shyft и т.п.
- Публичный `api.mainnet-beta.solana.com` подходит только для пробы: он режет запросы (HTTP 429).

В логах API-ключ маскируется (`api-key=***`).

## Структура проекта

```
src/
  index.ts              точка входа, сборка компонентов, корректная остановка
  config.ts             настройки из .env, пресеты фильтров
  listener.ts           подписка на логи pump.fun (создания и сделки), вотчдог переподключения
  activity.ts           статистика сделок за окно наблюдения и её проверка
  sniper.ts             оркестратор: фильтры → покупка → позиция, лимиты, бюджет, причины отказов
  positions.ts          позиции, TP/SL/трейлинг/таймаут, продажа с повторами
  journal.ts            журнал сделок (JSONL)
  report.ts             отчёт по журналу (npm run report)
  pump/events.ts        парсер CreateEvent и TradeEvent (Anchor events из логов)
  pump/bondingCurve.ts  PDA, раскладка аккаунта кривой, формулы покупки/продажи, mcap
  filters/              фильтры безопасности и загрузка метаданных
  trader/
    paper.ts            бумажная торговля: виртуальный кошелёк и реалистичное исполнение
    pumpPortal.ts       реальные сделки через PumpPortal
    guard.ts            проверка и симуляция транзакции перед подписью
    txSender.ts         отправка с переотправкой и ожиданием подтверждения
test/                   юнит-тесты (в т.ч. на реальных событиях из mainnet)
```

## Разработка

```bash
npm test            # юнит-тесты (vitest)

```

## Идеи для следующих версий

- Отправка через Helius Sender или Jito bundles для приоритета в блоке.
- Частичный тейк-профит (например, продать 50% на x2, остальное держать с трейлингом).
- Отслеживание цены в PumpSwap после миграции вместо немедленной продажи.
- Telegram-бот: уведомления о сделках и управление командами.
- Проверка истории создателя (сколько токенов он запускал и как они закончились).
